# login-service

本地的登录记录服务。也是 AI 员工流水线的**靶子**——03 本地开发动的是这里，
06 部署验证发的也是这里。

## 做什么

- `POST /login` `{"user_id":"u042"}` —— 记一次登录
- `GET /api/daily[?day=YYYY-MM-DD]` —— 某天的登录数，默认今天
- `GET /` —— 一个很小的后台页面，显示上面那个数
- `GET /metrics` —— 请求数、登录数、请求耗时 p99
- `GET /healthz` —— 存活 + 当前版本号

## 数据

**只有一份事实源：`data/logins.jsonl`**，只追加，不重写。

| 文件 | 是什么 | 丢了怎么办 |
|---|---|---|
| `data/logins.jsonl` | 原始登录记录 | 丢了就真丢了——别的东西都从它算 |
| `data/daily_cache.json` | 从原始记录算出来的每日汇总 | 重算即可 |

同一个人一天登录多次就有多条原始记录。"今天有多少人登录过"要去重，
去重是聚合的事，不是记录的事。

## 起

```bash
make test                      # 跑测试
make run                       # :8080，数据在 data/
make run PORT=:8081 VERSION=v2 # 灰度：起第二个实例，换端口换数据目录
curl -s localhost:8080/healthz
curl -s 'localhost:8080/api/daily?day=2026-09-10'
```

## 灰度怎么走

这个服务本身无状态，状态全在数据目录里。所以灰度是**两个进程**：

1. 新版本起在另一个端口，指**同一份**数据目录（只读路径要能同时读）
2. 观测新实例的 `/metrics`
3. 观测窗口走完，把流量切过去，旧实例收 `TERM` 干净退出

回滚就是把上一步反过来：切回旧实例，旧实例一直在跑或能立刻再起。
