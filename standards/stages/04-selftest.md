# 阶段 04：自测

> 产出证据，不是产出结论。

## 职责

**只**产出**可复现的证据**：命令、退出码、失败用例输出。

**不**下"没问题了"的结论——那是 05 审查的活。"我自己测过了"这句话在流水线里没有位置，因为它是**不可复现的断言**。

## 入口条件

上游（03 本地开发）须交付：

- 变更 diff
- 每条失败上报的 `where`/`cause`/`evidence` 三件套

拿不到就打回 03——**没有证据的变更不自测**，测了也只是把"他说好了"再复述一遍。

## 出口条件

下游（05 对抗式审查）接受这份交付，当且仅当：

- 测试报告，含：测试命令、**退出码**、失败用例的完整输出
- 回归套件**全绿**（exit 0）
- 变更触及线上数据路径（迁移/回填/删除）时：在**测试环境**跑通方案与回滚方案，产出命令日志
- 明确列出**未覆盖**的场景（哪怕为空也要显式写）

## 专属规范

- 执行 [`delivery.md`](../delivery.md) 准则 1「要测试」。
- 复杂变更要在测试环境验证**变更方案和回滚方案**——本机通过不算。
- 覆盖要从场景、接口、代码三个维度看，不是只看行覆盖率。
- 未覆盖的东西要写出来。**审查者靠这张清单决定审什么**；不写等于把风险藏起来。

## 报给前台（`前台事实`）

形状和四条规矩见 [index.md](index.md#契约块规则只有一个事实源)。这一段通常报：

| 报什么 | 类型 | 取自 |
|---|---|---|
| 量出来的数字（延迟、内存、耗时） | `observation` | `测试命令` 逐条的耗时、`回归套件` |
| 确认失败的用例及其位置与原因 | `failure` | `失败用例` + `失败用例的完整输出` |
| 本段挡不住、要人拍板的 | `decision_needed` | `待决策` |

**本段不下结论，但本段报事实。**「0 条失败用例」是一条 `observation`，
不是「没问题了」——后者是 05 的活。报了数字不等于判了性质。

## 闸门

- `[闸门]` 回归套件 exit 0。有退出码才算跑过。
- `[闸门]` 测试报告含 `未覆盖场景` 字段（可为空数组，但字段必须在）。
- `[闸门]` 触及线上数据路径的变更，必须有测试环境的方案执行与**回滚方案预演**两份命令日志。
- `[闸门]` 报告里不得出现无退出码的测试摘要。

## 驳回权

| 什么情况 | 打回给谁 | 附什么 |
|---|---|---|
| 03 未交付可复现证据，或失败上报缺 `where`/`cause` | 03 | 缺哪条 |
| 回归套件不绿 | 03 | 失败用例输出 |
| 变更触及数据路径但没做测试环境预演 | 03 | 缺的那份日志 |

## 证据

测试命令 + 退出码 + 失败用例输出 + 测试环境的方案/回滚日志路径 + 未覆盖场景清单。

## 反例

- ❌ "我人工检查过了。" → 不可复现，等于没测。
- ❌ "测试已在之前跑过。" → 之前的结论不等于这次变更的结论。
- ❌ 只有行覆盖率数字，说不出哪些**场景**没覆盖。
- ❌ 数据迁移只在本机跑通就往下走 → 准则 1 明确要求测试环境。

## 契约（机器可读）

`未覆盖场景` 用 `present` 而不是 `nonempty`：这个字段存在的意义是"说清楚没覆盖什么"，
空数组（"没有未覆盖场景"）是一个合法的、明确的回答；缺字段不是。

```json
{
  "id": "04",
  "name": "自测",
  "produces": "测试报告",
  "entry": [
    { "from": "变更卡", "field": "diff", "check": "nonempty" },
    { "from": "变更卡", "field": "失败记录", "check": "present" }
  ],
  "exit": [
    { "field": "测试命令", "check": "nonempty" },
    { "field": "退出码", "check": "equals", "value": 0 },
    { "field": "未覆盖场景", "check": "present" },
    {
      "when": [{ "field": "触及数据路径", "check": "is_true" }],
      "field": "测试环境日志",
      "check": "nonempty"
    }
  ],
    "publish": "前台事实",
"reject_to": "03"
}
```
