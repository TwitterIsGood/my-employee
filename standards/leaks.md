# 别把内网端点和密钥带上公开仓库

这个仓库是公开的。**教训该留下，端点标识不该。**

## 已经犯过一次

`standards/resilience.md` 从建仓起就把内网代理的真实域名写在正文里，一路推到
`origin/main`，谁都没发现——因为没有任何东西会在意。不是哪个人不小心：
**"我提交前注意一下"的第一个版本，恰好就是漏掉它的那一次。**

事后处置：正文改写成 `<内网代理>` / `<内网机>` / `<机器名>` 这类占位符，
`front/im.sh` 里写死的工作区 id 改成必须由环境变量给（`${MULTICA_WS:?…}`）。
所以你在那些文件里看到尖括号占位符，不是没写完，是**故意的**，别改回去。

## 闸门

```
make check-leaks      # 只跑这一道
make test             # 全量，含这一道
```

`internal/leaks` 扫 `git ls-files` 列出的每个文件，命中三类：

| 类别 | 例子 | 为什么 |
|---|---|---|
| **密钥值** | `sk-…`、`ghp_…`、`AKIA…`、`Bearer …`、`-----BEGIN … PRIVATE KEY-----` | 这类东西进了历史就追不回来，只能换掉重发 |
| **IP 字面量** | 除 `127.*` / `0.0.0.0` / `255.255.255.255` 外的任何 IPv4 | 公开仓库里出现一个 IP，几乎总是机器地址 |
| **域名** | 结尾是常见 TLD、又不在白名单里的点分名字 | 内网代理、内部服务都是这个形状 |

**它只扫被跟踪的文件。** gitignore 掉的东西本来就不进仓库，对它们喊是噪音——
`local/` 里正住着含凭据的 settings 文件。

## 放行两种东西

1. **本来就公开的主机名** → 加进 [`internal/leaks/leaks.go`](../internal/leaks/leaks.go) 的 `allow` 表。
   那是一次明确表态：加之前先问一句"这个域名公开出去有事吗"。
2. **实例专属的名字** → 写进 `local/leaks-deny.txt`（gitignored，一行一个）。
   这是给已经知道敏感、但**不肯写进仓库**的名字用的——名单本身要是进了仓库，
   那闸门就成了出口。命中时它也不会把你写的名字回显出来。

```sh
# local/leaks-deny.txt —— 这个文件不进仓库
内网代理的真实域名
那台机器的名字
```

## 两条校准原则

- **宁可漏，不要吵。** `.sh` 和 `.int` 都是真 TLD，一个撞 shell 脚本扩展名
  （`im.sh`），一个撞 Go 的 `fs.Int`——两个都没收。闸门喊多了，人就把它关了，
  那比没有闸门更糟。
- **闸门自己也在扫描范围里。** 所以 `internal/leaks` 里只写通用形状，
  绝不写要防的那几个具体名字；测试样例也是拼出来的。它不认"这是测试数据"
  这种理由——发布出去的仓库同样不认。
